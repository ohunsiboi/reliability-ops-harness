Reliability Ops Harness · Capstone (7A, Path A)

Multi-Asset Escalation System

A reliability engineer reviews every asset in the database, decides which failures are costly enough to escalate, and gets a spare-parts justification memo routed to the right approval tier automatically. This page runs the deterministic parts — the math, the escalation loop, and a template preview of the eval/guardrail — so you can see the whole system shape at a glance. The real AI-drafted version, with genuine tool use over a live MCP server, runs in Claude Code: github.com/ohunsiboi/reliability-ops-harness.

01 · Thresholds

Same thresholds used by the real workflow in CLAUDE.md: $15,000 to escalate, $40,000 to require VP-tier sign-off instead of manager sign-off.

02 · Asset Database

Edit hourly cost or failure records directly below — every number recalculates live, and feeds the escalation review when you run it.

Click "Run Escalation Review" above to check every asset against the thresholds.

04 · What Changed Since 6C

  • Iteration 1 — MCP server + real multi-asset data. 6C read one hardcoded JSON file for one asset. This build queries a real SQLite database through a real MCP server exposing list_assets, get_asset_metrics, and get_failure_log — verified with a live JSON-RPC handshake before ever touching Claude Code.
  • Iteration 2 — an actual agent loop. 6C was one asset in, one memo out. This build loops across every asset, checks its real cost, and branches — skip or escalate — the way you just saw above.
  • Iteration 3 — a deeper eval and a real guardrail. 6C's eval checked two things. This one checks five, and feeds a guardrail that changes the approval tier itself once cost crosses $40,000 — manager sign-off vs. VP sign-off.
